# 내 캘린더 — 노션 스타일 캘린더 + 할 일 (1단계 MVP)

혼자 쓰는 캘린더 + 할 일 관리 웹앱입니다. 데이터는 브라우저(IndexedDB)에만 저장됩니다. 로그인이나 서버는 없습니다.

## 쓰는 방법 (3가지 중 하나)

### A. 설치 없이 브라우저로 쓰기 (추천, 회사 PC)
GitHub Pages에 배포된 주소를 엽니다. 예: `https://<아이디>.github.io/<저장소이름>/`
- Node.js 설치나 스크립트 실행이 필요 없어서 회사 보안 정책에 걸리지 않습니다.
- 인터넷이 끊겨도 한 번 열어 둔 앱은 계속 열립니다.

**바탕화면 아이콘 만들기**
- **Edge**: 주소를 연 뒤 오른쪽 위 `…` → **앱** → **이 사이트를 앱으로 설치** → 설치 후 나오는 창에서 **바탕 화면에 바로 가기 만들기**를 체크합니다.
- **Chrome**: 주소창 오른쪽의 설치 아이콘(모니터 모양), 또는 `⋮` → **전송, 저장, 공유** → **바로가기 만들기** → **창으로 열기**를 체크합니다.
- 설치가 막혀 있으면: 바탕화면 빈 곳을 우클릭 → **새로 만들기 → 바로 가기** → 위 주소를 붙여넣고 이름을 `내 캘린더`로 정합니다.

### B. 내 PC에서 직접 실행 (Node.js 필요)
폴더 안의 **`내 캘린더 실행.cmd`** 를 더블클릭합니다. 첫 실행 때만 필요한 파일을 내려받습니다.

터미널로 직접 실행할 때는 **한 줄씩 따로** 입력합니다. Windows PowerShell 5에서는 `&&`가 안 됩니다.
PowerShell에서 "스크립트를 실행할 수 없습니다" 오류가 나면 `npm` 대신 `npm.cmd`를 씁니다.
```bat
cd calendar-app
npm.cmd install
npm.cmd run dev
```

### C. 개발용 (Mac / Linux / Git Bash)
```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/ 에 정적 파일 생성
```

> ⚠️ 일정 데이터는 **각 브라우저의 각 주소마다 따로** 저장됩니다. 그래서 A(github.io)와 B(localhost)의 데이터는 서로 보이지 않습니다.
> 옮기려면 사이드바 아래 **내보내기**로 JSON 파일을 받은 뒤, 다른 쪽에서 **백업 열기**로 불러옵니다.

## GitHub Pages 배포 설정 (처음 한 번)
1. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 바꿉니다.
2. 그다음부터는 `main` 브랜치에 push할 때마다 `.github/workflows/deploy.yml`이 자동으로 빌드하고 배포합니다.
3. 배포 주소는 **Actions** 탭의 실행 결과나 **Settings → Pages**에서 확인합니다.

GitHub Pages는 무료 계정이면 **공개 저장소에서만** 쓸 수 있습니다. 비공개 저장소에서 쓰려면 GitHub Pro 이상이 필요합니다.
일정 데이터와 API 키는 저장소에 올라가지 않고 각자의 브라우저에만 있습니다. 그래서 코드를 공개해도 개인 데이터는 노출되지 않습니다.

## 기능
- 월 / 주 / 일 보기, 오늘 이동, 이전·다음 이동, 사이드바 미니 달력
- 일정: 빈 칸을 클릭하면 1시간 일정, 드래그하면 원하는 길이로 생성됩니다. 블록을 끌어 옮기고 아래쪽 가장자리를 끌어 길이를 바꿉니다. 종일 칸이나 월간 칸을 더블클릭하면 종일 일정이 생깁니다.
- 할 일: 체크, 마감일, 우선순위, 태그. 사이드바에 오늘 / 인박스 / 예정 / 완료됨 / 태그별 목록이 있습니다.
- **타임 블로킹**: 사이드바의 할 일을 주·일 보기의 시간 칸에 끌어다 놓으면 30분 블록이 됩니다. 종일 칸이나 월간 칸에 놓으면 마감일이 바뀝니다.
- 상세 패널(오른쪽 사이드 피크): 제목, 속성 표, 메모가 있고 자동 저장됩니다. 메모 줄 맨 앞에서 `/`를 누르면 블록 메뉴가 열립니다.
- 한국어 빠른 입력: `내일 3시 치과 #건강 !높음`, `다음주 금요일 오후 2시~4시 회의`, `11월 30일 보고서 마감`
- 커맨드 팔레트(Ctrl/⌘+K): 검색, 새 일정 / 새 할 일(자연어), 보기 전환
- JSON 내보내기·가져오기(백업), 다크 모드, 모바일 레이아웃
- **캡처로 일정 추가**: 스크린샷, 사진, PDF, 텍스트, .ics 파일에서 일정을 찾아 줍니다. 아래 사용법을 보세요.

## 캡처·파일로 일정 추가
1. 화면을 캡처한 뒤 앱에서 **Ctrl/⌘+V**를 누릅니다. 파일을 화면에 끌어다 놓거나, 툴바의 **캡처로 추가** 버튼(단축키 `I`)을 눌러도 됩니다.
2. **일정 찾기**를 누르면 Claude가 이미지와 PDF를 읽고 일정과 할 일을 뽑아냅니다.
3. **검토 화면**에서 원본 이미지와 나란히 비교하면서 모든 칸을 바로 고칠 수 있습니다.
   - 노란 칸: AI가 확신하지 못한 값입니다(흐린 글씨, 추측한 시간 등). 이유가 함께 표시되고, 값을 고치거나 **맞아요**를 누르면 사라집니다.
   - 빨간 칸: 저장할 수 없는 오류입니다(제목 없음, 종료가 시작보다 빠름, 날짜 형식 오류). 고치거나 선택을 해제해야 추가 버튼이 켜집니다.
   - 같은 날 같은 제목의 항목이 이미 있으면 중복으로 보고 선택을 미리 해제해 둡니다.
   - 항목마다 근거가 된 원문이 표시되고, 일정/할 일 전환, 삭제, 직접 추가가 됩니다.
4. **선택한 N개 추가**를 누르면 캘린더에 들어갑니다.

AI 분석에는 **Claude API 키**가 필요합니다. 사이드바 아래 ⚙ 또는 가져오기 창의 **설정**에서 넣으세요.
키는 이 브라우저의 localStorage에만 저장되고 Anthropic API로만 전송되므로, 공용 컴퓨터에서는 쓰지 마세요.
기본 모델은 Claude Opus 5.5이고, 설정에서 Sonnet 5.5나 Haiku 5.5로 바꿀 수 있습니다.
키가 없어도 `.ics` 파일과 한 줄에 하나씩 적은 텍스트(빠른 입력 문법)는 가져올 수 있습니다.

## 단축키
| 키 | 동작 |
|---|---|
| Ctrl/⌘ + K | 커맨드 팔레트 |
| Ctrl/⌘ + V | 캡처한 이미지 붙여넣어 일정 가져오기 |
| I | 캡처·파일로 일정 추가 |
| N | 새 일정 |
| T | 새 할 일 입력칸으로 이동 |
| M / W / D | 월 / 주 / 일 보기 |
| ← / → | 이전 / 다음 |
| . | 오늘 |
| Ctrl/⌘ + \ | 사이드바 접기 |
| Esc | 패널·팔레트 닫기 |

## 구조
```
src/
  types.ts            데이터 모델 (Item: event | task)
  db.ts               Dexie(IndexedDB) + 생성·수정·삭제 + 백업
  store.ts            Zustand UI 상태 (보기, 날짜, 선택 항목 등)
  lib/date.ts         날짜 유틸 (월요일 시작, ko)
  lib/items.ts        캘린더 배치, 겹침 레이아웃, 섹션 필터
  lib/parse.ts        한국어 자연어 빠른 입력 해석
  lib/ai.ts           Claude API로 일정 추출 (구조화 출력, 필요할 때만 로드)
  lib/importFiles.ts  AI 설정 저장, 이미지 축소·PDF·텍스트 변환
  lib/drafts.ts       검토용 임시 항목, 검증, .ics·텍스트 해석, 중복 확인
  components/         Sidebar, MiniCalendar, TaskList, Toolbar,
                      TimeGrid(주/일), MonthView, PeekPanel, CommandPalette,
                      ImportDialog(가져오기·검토), SettingsDialog
```
디자인 토큰(색, 테두리, 태그 9색, 다크 모드)은 `src/index.css`의 CSS 변수에 모여 있습니다.
